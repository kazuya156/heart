# M20: 長い選択肢のレイアウト

2026-10-25追記：本文ページ分割・導入選択肢・鉛筆の質問ラベルにKENより基本確認の報告。確認用文章とITEM_01の質問ラベルは元の仮データへ復帰済み。以下は確認時の手順記録。全補助チェック/全入力/全解像度の合格を示すものではない。

ブランチ: feature/m20-choice-layout。M19の本文ページ分割とM18の確認用データを含む。セットアップ再実行/シーン編集不要。

## 問題と変更

KENの1280×720画像で、導入選択肢の約50字が固定高84から上下へはみ出し、他方の選択肢と重なっていた。

共通ChoicePanelが実行時にラベルの折り返し後の高さを測り、文字サイズを保ったままボタン高を広げる。左右24/上下14の余白、18の間隔、最小高84を既定値にする（ChoicePanel Inspectorで調整可能）。ラベルの旧marginを余白と二重適用しない。

既存Optionsの表示位置/範囲を受け継ぐViewportを実行時だけ作り、全体が高すぎる場合は縦スクロールとスクロールバーを表示する。表示範囲外はRectMask2Dで隠す。全文を短縮/省略せず、全選択肢を比較して選べる。横スクロール/自動縮小は使わない。

短い選択肢は従来どおり最小高で中央配置する。選択肢の表示中に画面サイズが変わった場合は行高を再計算する。所持品詳細の表示中などSetInteractionEnabled(false)では、ボタン・スクロール・バー操作を止める。閉じた後の古い入力、表示開始フレームの選択、二重選択の既存ガードは維持する。

台本ID/分岐、取得する/しないの意味、質問判定は変更しない。質問画面の6ラベルは別UIなので、M18の55字ラベルの表示確認は別に必要。

## 確認

1. Play停止→Fetch origin→feature/m20-choice-layoutへ切替→Unityコンパイルを待つ。
2. Play中、Sea of Memories → Checks → Choice Layout (Play mode)を実行。passedログと赤エラーなしを確認する。これは本編と別の一時Canvasで動作し、終了時に片付ける。
3. START後の60/120/180字を進めて導入選択肢を表示。文字がボタン内に収まり、二つの文章が重ならず、両方の「【末尾】」が読めるか確認する。文字サイズの極端な縮小がないかも確認する。
4. スクロールバーが出る場合、ホイール/バー/ドラッグで下端まで読めるか確認する。スクロールだけで選択が確定しないこと、下の選択肢をクリックできることを確認する。
5. Aをクリックして探索へ進む。Play停止・再開してBでも同じ探索へ進むことを確認する。
6. アイテム説明後の「取得する/取得しない」が短いまま中央配置され、選択と読み返し中の操作停止が従来どおりか確認する。
7. Full HD / 1280×720で確認。Game表示倍率0.7による見かけの文字サイズと、ゲーム内文字サイズを区別する。
8. 続けて鉛筆の説明/読み返し/55字の質問ラベル/質問台詞もM18・M19の手順で確認する。

表示領域の幅より一文字自体が大きいなど、任意の極端なUI設定まで保証する機能ではない。本番文章の読みやすさ/行末の区切りは実画像で調整する。

## 補助チェック

実際のChoicePanel/TMP/VerticalLayoutGroupで長文の行高と間隔、スクロール/クリップ/バー、文字サイズ維持、詳細モーダル中のロック/再開、短文への復帰、表示開始フレームの選択禁止と一度だけの確定を検証する。確認用に英語本文を使い、日本語は本編サンプルで目視する。

作業環境にUnity/C#コンパイラがなく、チェック実行・コンパイル・表示確認は未実施。コードレビューとリモート保存内容の照合を行う。既存MainSceneや台本/定義アセットはこの工程で変更しない。M18の一時データは確認後に復元する。

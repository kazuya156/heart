# M09：虫眼鏡カーソルとホバー表示

## 今回の目的

詳細設計書v0.1の5.8、6.1、受け入れテストT13に沿って、家具とアイテムにポインターを重ねたときの反応を追加します。M08のシーン保存コミット847ea2fが土台です。

- 通常の虫眼鏡は64、調べられる家具・未取得アイテム上では84へ瞬時に変更します（基準1920×1080のCanvas単位）。
- 有効な対象には薄いシアンの枠を表示します。
- 説明・取得判断・所持品詳細・フェード中は背景の枠とカーソル拡大を解除します。
- 取得済みアイテム、2品取得済み家具にはホバー反応を出しません。
- クリック・取得・質問・分岐・台本・フェードのルールは変更しません。

本番のカーソル画像と対象の輪郭素材は未受領です。虫眼鏡は起動時に生成する白＋黒縁の仮Sprite、ハイライトは既存の仮ボタンに合わせた長方形の細い枠です。本番素材を受け取ったら差し替えます。

## Unityでの取り込み

1. Play停止 → Ctrl+S。
2. GitHub DesktopでFetch origin → Current branch → `feature/m09-cursor-hover`。
3. Unityのコンパイルを待ち、`Assets/Scenes/MainScene.unity`を開きます。
4. **Sea of Memories → 09 - Add Cursor and Hover**。
5. Ctrl+S → Play → START。
6. ROOMのDESK/BED/WINDOW、その拡大画面の未取得アイテムにマウスを重ねます。

メニュー09はGameSystemsにCursorOverlay、Canvas直下にクリックを遮らないImage、家具3個と再利用するアイテムボタン2個にHotspotViewと枠を追加します。クリックのイベントとボタンの位置は保持します。途中まで作成済みの場合も既存の設定を上書きせず停止します。

編集画面ではカーソル画像を非表示にしています。Play時に仮画像が作られるため、新しい画像ファイルを手作業で配置する必要はありません。

## ファイルと責務

| ファイル | 担当 |
| --- | --- |
| `Assets/Scripts/UI/CursorOverlay.cs`（新規） | マウス座標をCanvas座標に変換し、Imageを追従させる。SetHover/SetVisible、64/84の切替、OSカーソルの非表示と復元、仮Spriteの作成・破棄 |
| `Assets/Scripts/UI/HotspotView.cs`（新規） | PointerEnter/Exitを受け、クリック可能な対象だけ枠と拡大を要求。SetAvailable/SetHighlightを提供。Phaseや取得・質問データは変更しない |
| `Assets/Scripts/Gameplay/ExplorationController.cs` | 既存のクリック可否更新と同時にHotspotView.SetAvailableへ通知。取得済み・家具完了・モーダル中の反応を解除 |
| `Assets/Editor/SeaOfMemoriesCursorSetup.cs`（新規） | メニュー09でカーソルImage、5個のHotspotViewとシアン枠を設定 |
| `Assets/Scenes/MainScene.unity`（Unityで保存） | 生成したコンポーネント・Image・枠・参照を保持 |

uGUIのPointerEnter/Exitは「ポインターがそのUIへ入った／出た」という通知です。それに加え、HotspotViewは毎フレーム、対象が操作可能か・ポインターがまだ範囲内かを確認します。これにより、ポインターを動かさずにポップアップを開いたり対象が消えたりしても、ハイライトを残しません。

複数の通知が同じフレームで入れ替わっても、各対象の要求をCursorOverlayがまとめます。最後にカーソルの位置・大きさを反映します。カーソルImageと枠のImageは全てRaycast TargetをOFFにして、元のButtonへ入力が届く構造です。

## Inspectorでの調整

GameSystems → CursorOverlay：

| 項目 | 初期値・用途 |
| --- | --- |
| Normal Size | 64。通常の大きさ |
| Hover Size | 84。調査可能な家具・アイテム上の大きさ |
| Normal Sprite / Hover Sprite | 本番の通常／拡大画像。空なら仮画像を使用。拡大画像だけ空なら通常画像を拡大 |
| Pointer Pivot | 仮画像のレンズ中心。画像を差し替えたら、この値でレンズとクリック位置の見た目を合わせる |

各家具／アイテムボタン → HotspotView：

- Highlight Color：枠の色と濃さ。初期値は薄いシアン。
- Highlight Frame：仮の長方形枠。将来の輪郭表示へ差し替え可能。
- Fallback Brightness：枠が未指定の場合に使う明度の加算値。

カーソルの中心位置は見た目だけの設定で、実際のクリック座標はマウス入力のままです。通常UIのSTART/BACK/質問/所持枠では虫眼鏡は通常サイズです。拡大は仕様の家具・アイテムだけに付けます。

## 動作確認（T13と回帰）

| 操作 | 正常な結果 |
| --- | --- |
| Play → ROOM | 虫眼鏡がマウスに追従。OS矢印と二重にならない。クリックができる |
| DESK/BED/WINDOWへ重ねる | 64→84へ瞬時に拡大し、その対象だけにシアン枠。外すと瞬時に解除 |
| 家具を開く | フェードを開始した瞬間に枠と拡大を解除。完了後、未取得アイテムに重ねると再び反応 |
| 未取得アイテム2個へ交互に重ねる | 対応する方だけ反応。調査・TAKE/LEAVEは以前どおり |
| アイテムを取得 | 消えた対象の枠が残らない。残った未取得品は引き続き反応 |
| 同じ家具で2品取得、合計3個以下 | 家具完了台詞→ROOM。完了した家具に重ねても拡大・枠が出ない |
| 説明／TAKE・LEAVE／読み返し中 | 背景の家具・アイテムの枠と拡大が出ない。読み返しの開閉後は操作可能な対象だけ反応が復帰 |
| 4個目・追及・両エンド | ホバー追加で進行が変わらず、4個目優先・3問上限・最後の返答後の結末を維持 |
| Gameビューのサイズ変更 | カーソルのレンズがマウス位置に追従し、表示スケール変更で大きくずれない |
| Gameビュー／ウィンドウ外へ移動 | カスタム画像を隠し、元のOSカーソル表示へ戻る。戻すと再び虫眼鏡。Editorでのフォーカス挙動も実機確認する |
| Alt+Tabで別ウィンドウへ移動 | OSカーソルが復帰。ゲームへ戻ると対象の上だけ正しい大きさと枠になる |
| Play停止 | OSカーソルが元の表示に戻り、仮画像は残らない |

カーソルはポップアップ・フェードより手前に描画しますが、入力は遮りません。フェード中も通常サイズの虫眼鏡は見えます。背景操作はM08の入力遮断を維持します。

作成環境で32個のC#ファイルの構文・ローカル変数スコープ・Phase更新元と、既存データ未変更を静的に確認しました。Unity/C#コンパイラはないため、実機でのコンパイル、描画位置、Pointer通知、フォーカス復帰は未確認です。T13の確認には上の操作が必要です。

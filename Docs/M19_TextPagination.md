# M19: 長い台詞のページ分割

ブランチ: feature/m19-text-pagination。M18の確認用文章を引き継ぐ。セットアップ再実行・シーン編集は不要。

## 確認できた問題

2026-10-25、KENの1280×720/Game表示倍率0.7の画像で、120字は操作案内と同じ高さまで詰まり、180字は台詞枠の外へ表示された。文字が読めることだけで合格としない。

## 変更

本文の文字サイズと枠は維持し、TMPの実際の折り返しと枠の高さに応じてページへ分ける。60/90字などの固定文字数で切らない。元の本文を保持し、文字インデックスとpageToDisplayで表示するため、タグや日本語を文字列切り取りで破損させない。

通常会話・アイテム説明・所持品の独立した読み返しに対応。

1. 文字送り中の入力は、現在ページを全文表示するだけ。
2. 表示後の入力は、続きのページがあればそのページの文字送りを開始。
3. 最終ページの表示後に入力した時点で、次の台詞・選択肢・取得処理・質問判定へ進む。

実際のページ送りはSE_01を一度再生し、全文表示だけでは鳴らさない。ページ内で背景/表情/音/揺れなどのノード開始処理を再実行しない。読み返しは従来どおり本文のみ。本編のPause/Resumeはページと文字位置を保持する。

心情文/未取得警告は従来どおり各ページを即時全文表示する。複数ページなら会話送りで続きを読み、最後のページに到達してから質問操作を許可する。警告はさらに次の入力で心情文へ戻る。短い既存メッセージの操作は同じ。

ページ割りは台詞/説明の表示開始時に計算する。解像度ごとの比較ではPlayを停止・再開する。会話途中に枠そのものや画面比率を変えた場合のページ再配置は今回の確認範囲外。

導入の選択肢ボタンと質問ラベルは文章用のページ送りとは別。M18の約50字/55字ラベルの収まりは引き続き確認する。

## 実機確認

1. Play停止→Fetch origin→新ブランチへ→Unityコンパイルを待つ。MainScene再生成不要。
2. Play中にSea of Memories → Checks → Text Paging (Play mode)を実行し、Consoleのpassedログ/エラーを確認する。本編とは別の一時オブジェクトで検証し、終了時に破棄する。
3. START直後の60/120/180字を読む。最初のクリックは今のページの全文、次で続き。最終ページの「【末尾】」まで枠内で表示され、文字サイズが変わらないか確認する。ページ数は枠と字体に依存する。
4. 180字の途中ページでEnter+クリックを重ね、1つの入力まとまりでページを飛び越さないか確認する。
5. 机の鉛筆説明120字と明示3行を読む。説明の最終ページまで読んでから取得選択肢が出ることを確認する。
6. 鉛筆を取得し、所持品で読み返して最後まで進める。別の会話の途中ページでも読み返しを開いて閉じ、同じページ/文字位置に戻るか確認する。
7. 鉛筆の質問台詞120字も最後まで表示した後に質問結果が確定するか確認。3問目も返答の最終ページ完了までEndingへ進まないことを確認する。
8. Full HDと1280×720でPlayを開始し直して確認する。選択肢・質問ラベルの窮屈さ/はみ出しは別途報告する。

## 補助チェックの内容と限界

Text Pagingチェックは実際のTMP/DialoguePlayer/ItemDetailsViewerを使い、改ページ・全文表示・完了一回・SE回数・Pause/Resume・即時文の最後のページでの操作解放・Stop時の通知解除・読み返し・空文字・タグ/改行を検証する。独立テスト用の英語本文を使うため、日本語の見た目と読みやすさはKENの画面で別に確認する。

従来Audioチェックの短文は専用の広いラベルへ入れ、1ページという試験の前提を明確にした。チェック自体をこちらの環境で実行したわけではない。作業環境にUnity/C#コンパイラがなく、コンパイル・補助チェック・実操作は未実施。
